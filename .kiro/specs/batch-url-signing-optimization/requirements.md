# 需求文档

## 简介

本文档定义了系统优化需求，包括批量 URL 签名优化、用户详情只读查看功能和错误提示格式优化。这些优化旨在提升系统性能、用户体验和信息展示的友好性。

## 术语表

- **Batch_Signing_Service**: 批量签名服务，负责一次性为多个文件 URL 生成带签名的临时下载链接
- **Signed_URL**: 带签名的临时下载 URL，包含访问凭证和过期时间
- **User_Detail_Viewer**: 用户详情查看器，以只读方式展示用户完整信息
- **Error_Formatter**: 错误格式化器，负责将错误信息按规定格式进行截断和展示
- **File_URL**: 文件在存储桶中的相对路径（key）
- **Expired_URL**: 带签名的完整下载 URL

## 需求列表

### 需求 1: 批量 URL 签名接口集成

**用户故事:** 作为开发者，我希望使用批量签名 API 一次性签名多个文件 URL，以减少 API 调用次数并提升页面加载性能。

#### 验收标准

1. 批量签名服务应提供一个方法，支持单次 API 调用签名最多 50 个文件 URL
2. 当文件 URL 数量超过 50 个时，批量签名服务应将其拆分为多个批次并顺序处理
3. 当发起批量签名请求时，批量签名服务应向 `/api/common/download/token/batch` 发送 POST 请求，携带文件 URL 列表
4. 当收到批量签名响应时，批量签名服务应使用所有签名 URL 及其过期时间更新本地缓存
5. 如果批量签名请求失败，批量签名服务应回退到逐个签名每个 URL
6. 批量签名服务应返回一个 Map，以原始文件 URL 为键，签名后的 URL 为值

### 需求 2: 分页数据批量签名处理

**用户故事:** 作为用户，我希望在查看包含图片的列表时页面加载更快，以获得更好的浏览体验。

#### 验收标准

1. 当页面获取分页数据时，系统应从响应中收集所有需要签名的文件 URL
2. 当收集到文件 URL 后，系统应使用批量签名服务进行批量签名
3. 当获取到签名 URL 后，系统应使用签名 URL 更新显示数据
4. 系统应仅签名未缓存或已过期的 URL
5. 当没有 URL 需要签名时，系统应完全跳过批量签名步骤

### 需求 3: 用户详情只读查看功能

**用户故事:** 作为管理员，我希望以只读模式查看用户详情，以便在不意外修改的情况下审查用户信息。

#### 验收标准

1. 用户管理页面应在每行用户的操作列中显示"查看详情"操作按钮
2. 当点击"查看详情"按钮时，系统应打开一个显示用户信息的模态对话框
3. 用户详情查看器应调用与编辑功能相同的 API 获取用户详情
4. 用户详情查看器应以禁用/只读状态显示所有用户字段
5. 用户详情查看器不应显示任何提交或保存按钮
6. 用户详情查看器应显示关闭按钮以关闭模态框
7. 当用户详情正在加载时，用户详情查看器应显示加载指示器

### 需求 4: 错误提示格式优化

**用户故事:** 作为用户，我希望错误信息以可读的格式显示，以便在不被长文本淹没的情况下理解错误内容。

#### 验收标准

1. 当显示错误信息时，错误格式化器应将每行限制为最多 20 个字符
2. 当显示错误信息时，错误格式化器应将总显示限制为最多 5 行
3. 当错误信息超过行数限制时，错误格式化器应截断剩余内容并追加省略号（"..."）
4. 错误格式化器应在换行时尽可能保留单词边界
5. 当错误信息在限制范围内时，错误格式化器应原样显示
6. 错误格式化器应在字符计数时正确处理中文和英文字符

### 需求 5: 批量签名类型定义

**用户故事:** 作为开发者，我希望批量签名 API 有正确的 TypeScript 类型定义，以便能够以类型安全的方式使用该 API。

#### 验收标准

1. 系统应定义 `BatchDownloadTokenRequest` 类型，包含 `fileUrls` 数组属性
2. 系统应定义 `BatchDownloadTokenItem` 类型，包含 `fileUrl` 和 `expiredUrl` 属性
3. 系统应定义 `BatchDownloadTokenResponse` 类型，包含 `items` 数组和 `expireAt` 时间戳
4. API 服务应使用这些类型进行请求和响应处理
